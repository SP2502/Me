How I learn

Build. Break. Understand. Improve.

I don't always try to understand everything before building. I usually learn by making something, discovering where my understanding is wrong, and investigating what actually happened.

The project becomes part of the learning process. A failure isn't just something to fix — it can reveal how the system works underneath.

About

Curiosity turned into systems.

I'm a Class 11 student interested in understanding how software and AI systems actually work.

I don't only want to use software. I'm interested in what happens underneath it — how APIs communicate, how services interact, how systems handle failures, how AI systems coordinate multiple steps, and how experiments can become usable systems.

WHY I BUILD

I started making projects because I wanted to grow with the world as the world is growing. Because I am curious.

WHAT I'M INTERESTED IN

Systems, AI agents, APIs, infrastructure, reliability, research workflows, and the strange problems that appear when different pieces of software have to work together.

WEATHER-DATA INFRASTRUCTURE

Universal

An infrastructure layer exploring how applications can work with weather data without directly depending on every individual provider.

WHY

Weather applications often need to understand the APIs and response formats of individual providers. I wanted to explore what happens when that complexity becomes an infrastructure problem instead.

WHAT I'M EXPLORING

Provider selection, failure handling, fallback behavior, response normalization, and a consistent API for applications.
