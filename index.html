01 About

Curiosity → systems

Curiosity turned into software.

I started making projects because I wanted to grow with the world as the world is growing. Because I am curious.

That curiosity gradually moved from writing code to understanding what happens between the pieces: how APIs interact, how systems choose between alternatives, what happens when something fails, and how separate components can work together.

I’m still learning. Most of my projects are experiments that became more serious as I discovered new problems inside them.

02 · Questions

The questions behind the projects.

I usually start with a question rather than a technology.

01

How should a system choose between multiple data providers?

Different providers expose different interfaces, capabilities and failure modes. Universal is an exploration of what should happen between the user request and those providers.

02

What should happen when one component of a system fails?

Failure is not an exception to system design. It is part of it. I’m interested in how systems can detect, isolate and recover from failures.

03

How can AI systems coordinate longer research workflows?

Cortex explores how planning, tool use, evidence collection and synthesis can be connected into a longer research process.

04

How much complexity should an abstraction hide?

A good interface should simplify the user experience without making the underlying system impossible to understand or debug.
