01 · INFRASTRUCTURE

Universal

EARLY DEVELOPMENT

Weather providers expose different APIs, formats, and failure modes. Universal is my attempt to put that complexity behind one interface.

CURRENT SYSTEM IDEA
Coordinates
→
Location
→
Provider
→
Fallback
→
Normalized API
WHY

Weather APIs expose different interfaces and behaviours. I wanted to explore what happens when that provider-specific complexity is moved behind one consistent system.

WHAT I'M BUILDING

A multi-provider weather-data layer that can resolve a location, work with providers, normalize their responses, and provide a consistent interface.

WHAT I'M INVESTIGATING

Provider selection, fallback behaviour, inconsistent schemas, reliability, and how much complexity an API abstraction should hide.

CURRENT STATE

Early development. Architecture and provider behaviour are still being explored.

02 · RESEARCH SYSTEM

Cortex

ACTIVE DEVELOPMENT

An open-source deep-research system for breaking complex questions into smaller tasks, gathering evidence, and combining the results into a structured answer.

RESEARCH WORKFLOW
Question
→
Planning
→
Research
→
Evidence
→
Synthesis
WHY

Complex research questions often require multiple searches, sources, comparisons, and reasoning steps rather than a single model response.

WHAT I'M BUILDING

A modular research system that can plan work, decompose questions, use tools, gather evidence, compare information, and produce structured results.

WHAT I'M INVESTIGATING

Planning, tool coordination, evidence handling, model orchestration, longer workflows, and reliability.

CURRENT STATE

Active development. The architecture is evolving as different research workflows are tested.

03 · WINDOWS SOFTWARE

AEGIS

BUILDING

A free Windows content blocker designed to reduce unwanted and adult content.

INPUT
→
DETECTION
→
DECISION
→
BLOCK
WHY

I wanted to explore how software can actively control what reaches a user's device instead of relying only on browser-level filtering.

WHAT I'M BUILDING

A Windows-first content-blocking system. The implementation is being developed before extending the project to Android.

CURRENT FOCUS

Detection, blocking behaviour, reliability, and understanding the boundaries of the Windows implementation.

NEXT

Continue the Windows implementation and investigate the architecture required for a later Android version.

04 · AUTONOMOUS AGENT

HOSTED

01 Experiment
02 Bot
03 System
04 Hosted
WHY

Minecraft provides a useful environment for experimenting with autonomous agents because actions have visible consequences inside a persistent world.

WHAT I BUILT

A Minecraft bot that evolved from a simple experiment into a more complete hosted system.

WHAT I LEARNED
